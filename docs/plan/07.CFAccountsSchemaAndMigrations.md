# Task 7 — CF-Accounts ScyllaDB Schema and Migrations

## Context

CF-Accounts owns the ScyllaDB schema for all tables it reads and writes: accounts, tenants, networks, subnets, api_keys, and provisioning_state. These tables are designed around read patterns (not normalization), as required by ScyllaDB's Cassandra-compatible data model.

Migrations are plain `.cql` files executed in filename order by the `tools/migrations` runner (built in Task 3). Migrations are idempotent — they use `IF NOT EXISTS`.

Reference: `docs/cf-private-network.md` sections 8.3 (what is created), 11.3 (ScyllaDB data modeling caution), and 14.2 (migration script location: `tools/migrations/scripts/`).

## Dependencies

Tasks 1, 2, and 3 must be complete.

### Migration 1: Keyspace

File: `tools/migrations/scripts/20240101001_create_keyspace.cql`

```cql
CREATE KEYSPACE IF NOT EXISTS cloudforge
    WITH replication = {'class': 'SimpleStrategy', 'replication_factor': '1'}
    AND durable_writes = true;
```

In production this will be replaced with `NetworkTopologyStrategy`. For local dev, `SimpleStrategy` with `replication_factor=1` is correct.

### Migration 2: Accounts table

File: `tools/migrations/scripts/20240101002_create_accounts.cql`

Design the `accounts` table for the following read patterns:
- Look up an account by `id` (primary key)
- Look up an account by `email` (separate table below)

```cql
USE cloudforge;

CREATE TABLE IF NOT EXISTS accounts (
    id UUID PRIMARY KEY,
    email TEXT,
    status TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

CREATE TABLE IF NOT EXISTS accounts_by_email (
    email TEXT PRIMARY KEY,
    account_id UUID,
    status TEXT
);
```

### Migration 5: API Keys table

File: `tools/migrations/scripts/20240101005_create_api_keys.cql`

Read patterns:
- Look up an API key record by `id`
- List all API keys for an `account_id`
- Look up an API key by its `key_hash` (for request authentication in CF-Router)

The raw secret is never stored. Only the BLAKE2b-256 hash is stored.

```cql
USE cloudforge;

CREATE TABLE IF NOT EXISTS api_keys (
    id UUID PRIMARY KEY,
    account_id UUID,
    key_hash TEXT,
    key_prefix TEXT,
    created_at TIMESTAMP,
    revoked_at TIMESTAMP
);

CREATE TABLE IF NOT EXISTS api_keys_by_account (
    account_id UUID,
    key_id UUID,
    key_prefix TEXT,
    created_at TIMESTAMP,
    revoked_at TIMESTAMP,
    PRIMARY KEY (account_id, created_at, key_id)
) WITH CLUSTERING ORDER BY (created_at DESC);

CREATE TABLE IF NOT EXISTS api_keys_by_hash (
    key_hash TEXT PRIMARY KEY,
    key_id UUID,
    account_id UUID,
    revoked_at TIMESTAMP
);
```

### tools/migrations module: main.go

File: `tools/migrations/main.go`

Implement the migration runner entry point. It must:
- Accept flags: `--hosts` (default `localhost:9042`), `--keyspace` (default `cloudforge`), `--scripts-dir` (default `./scripts`)
- Create a ScyllaDB session using `libs/scylladb/pkg/client`
- Run `pkg/migrate.RunMigrations`
- Print progress to stdout and exit 0 on success, exit 1 on failure

```go
package main

import (
    "context"
    "flag"
    "fmt"
    "log"
    "strings"

    "github.com/jtomasevic/cloud-forge-2/libs/scylladb/pkg/client"
    "github.com/jtomasevic/cloud-forge-2/libs/scylladb/pkg/migrate"
)

func main() {
    hosts := flag.String("hosts", "localhost:9042", "comma-separated ScyllaDB hosts")
    keyspace := flag.String("keyspace", "cloudforge", "target keyspace")
    scriptsDir := flag.String("scripts-dir", "./scripts", "directory containing .cql migration files")
    flag.Parse()

    cfg := client.Config{
        Hosts:    strings.Split(*hosts, ","),
        Keyspace: *keyspace,
    }

    session, err := client.New(context.Background(), cfg)
    if err != nil {
        log.Fatalf("failed to connect to ScyllaDB: %v", err)
    }
    defer session.Close()

    if err := migrate.RunMigrations(context.Background(), migrate.MigrationConfig{
        Session:    session,
        ScriptsDir: *scriptsDir,
    }); err != nil {
        log.Fatalf("migration failed: %v", err)
    }

    fmt.Println("migrations applied successfully")
}
```
