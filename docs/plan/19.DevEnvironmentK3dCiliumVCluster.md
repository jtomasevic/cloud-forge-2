# Task 19 — Dev Environment: k3d Cluster, Cilium, Envoy Gateway, vCluster, cert-manager

## Context

This task creates the local Kubernetes infrastructure for CloudForge development. A k3d cluster named `cloudforge-dev` is the host cluster where vCluster instances are provisioned, Cilium enforces network policies, and Envoy Gateway handles edge routing.

Reference: `docs/cf-private-network.md` section 12 (Developer Environment Proposal) and the architecture diagram in sections 6 and 7.

## Dependencies

Task 1 (repository skeleton and Makefile) must be complete. The following tools must be installed: `k3d`, `kubectl`, `helm`.

### Cluster setup script

File: `dev/k8s/cluster-up.sh`

This script creates a k3d cluster with the correct configuration for CloudForge development. Make it idempotent — if the cluster already exists, it is a no-op.

```bash
#!/usr/bin/env bash
set -euo pipefail

CLUSTER_NAME="cloudforge-dev"
CLUSTER_API_PORT=6550
# Host LB ports (defaults avoid 8080/8443 collisions); override: CF_K3D_LB_HTTP_PORT / CF_K3D_LB_HTTPS_PORT
: "${CF_K3D_LB_HTTP_PORT:=18080}"
: "${CF_K3D_LB_HTTPS_PORT:=18443}"

if k3d cluster list | grep -q "${CLUSTER_NAME}"; then
    echo "Cluster ${CLUSTER_NAME} already exists — skipping creation"
    exit 0
fi

echo "Creating k3d cluster: ${CLUSTER_NAME}"
k3d cluster create "${CLUSTER_NAME}" \
    --api-port "${CLUSTER_API_PORT}" \
    --port "${CF_K3D_LB_HTTP_PORT}:80@loadbalancer" \
    --port "${CF_K3D_LB_HTTPS_PORT}:443@loadbalancer" \
    --k3s-arg "--disable=traefik@server:0" \
    --k3s-arg "--flannel-backend=none@server:0" \
    --k3s-arg "--disable-network-policy@server:0" \
    --wait

echo "Cluster ${CLUSTER_NAME} created successfully"
echo "KUBECONFIG: $(k3d kubeconfig get ${CLUSTER_NAME})"
```

**Key flags explained:**
- `--disable=traefik`: disable k3s's built-in ingress controller (Envoy Gateway replaces it)
- `--flannel-backend=none`: disable flannel CNI (Cilium replaces it)
- `--disable-network-policy`: disable k3s's network policy controller (Cilium handles this)
- Port mappings (defaults): `18080` → LB HTTP (Envoy Gateway HTTP once installed), `18443` → LB HTTPS. Override with `CF_K3D_LB_HTTP_PORT` / `CF_K3D_LB_HTTPS_PORT` if these collide locally.

### Cilium installation script

File: `dev/k8s/install-cilium.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

CILIUM_VERSION="1.15.4"

echo "Installing Cilium ${CILIUM_VERSION}"

helm repo add cilium https://helm.cilium.io/ --force-update
helm repo update

helm upgrade --install cilium cilium/cilium \
    --version "${CILIUM_VERSION}" \
    --namespace kube-system \
    --set image.pullPolicy=IfNotPresent \
    --set ipam.mode=kubernetes \
    --set kubeProxyReplacement=false \
    --set policyAuditMode=true \
    --set hubble.enabled=true \
    --set hubble.relay.enabled=true \
    --wait

echo "Cilium installed. Verifying..."
kubectl rollout status daemonset/cilium -n kube-system --timeout=120s
echo "Cilium ready"
```

**Note:** `policyAuditMode=true` for dev — policies are observed but not enforced. This allows provisioning flows to be tested without breaking connectivity in the dev environment. Integration tests that verify isolation MUST set `policyAuditMode=false` on a separate cluster or temporarily override this setting.

### Envoy Gateway installation script

File: `dev/k8s/install-envoy-gateway.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

ENVOY_GW_VERSION="1.0.2"

echo "Installing Envoy Gateway ${ENVOY_GW_VERSION}"

helm repo add envoy-gateway https://charts.envoyproxy.io --force-update
helm repo update

helm upgrade --install envoy-gateway envoy-gateway/gateway-helm \
    --version "${ENVOY_GW_VERSION}" \
    --namespace envoy-gateway-system \
    --create-namespace \
    --wait

# Install the GatewayClass
kubectl apply -f - <<EOF
apiVersion: gateway.networking.k8s.io/v1
kind: GatewayClass
metadata:
  name: cloudforge
spec:
  controllerName: gateway.envoyproxy.io/gatewayclass-controller
EOF

echo "Envoy Gateway installed and GatewayClass 'cloudforge' created"
```

### vCluster CRDs and Helm chart

File: `dev/k8s/install-vcluster.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

VCLUSTER_VERSION="0.19.5"

echo "Installing vCluster Helm chart (CRDs only) ${VCLUSTER_VERSION}"

helm repo add loft-sh https://charts.loft.sh --force-update
helm repo update

# Install only the chart definition — actual vCluster instances are
# provisioned dynamically by CF-Provisioner.
helm upgrade --install vcluster-operator loft-sh/vcluster-k8s \
    --version "${VCLUSTER_VERSION}" \
    --namespace vcluster-system \
    --create-namespace \
    --set "vcluster.image=ghcr.io/loft-sh/vcluster:${VCLUSTER_VERSION}" \
    --wait

echo "vCluster operator/CRDs installed"
```

### CloudForge namespace and self-signed CA

File: `dev/k8s/setup-cloudforge-namespace.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

kubectl create namespace cloudforge-control-plane --dry-run=client -o yaml | kubectl apply -f -

# Self-signed ClusterIssuer for dev TLS
kubectl apply -f - <<EOF
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: cloudforge-selfsigned
spec:
  selfSigned: {}
EOF

echo "Namespace and ClusterIssuer created"
```

### Makefile targets

Add the following targets to the root `Makefile`:

```makefile
.PHONY: k3d-up k3d-down k3d-install-deps

k3d-up:
	dev/k8s/cluster-up.sh

k3d-install-deps: k3d-up
	dev/k8s/install-cilium.sh
	dev/k8s/install-envoy-gateway.sh
	dev/k8s/install-vcluster.sh
	dev/k8s/install-cert-manager.sh
	dev/k8s/setup-cloudforge-namespace.sh
	@echo "All k8s dependencies installed"

k3d-down:
	dev/k8s/cluster-down.sh
```

## Acceptance Criteria

- `make k3d-up` creates the `cloudforge-dev` cluster without errors
- `make k3d-install-deps` installs all four components (Cilium, Envoy Gateway, vCluster, cert-manager)
- `kubectl get nodes` shows the cluster nodes
- `kubectl get pods -n kube-system` shows Cilium pods running
- `kubectl get pods -n envoy-gateway-system` shows Envoy Gateway pods running
- `make k3d-down` deletes the cluster
- All scripts are idempotent (safe to run twice)
- `make k3d-up && make k3d-install-deps` completes in under 5 minutes on a standard developer laptop
