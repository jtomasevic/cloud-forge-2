# Task 26 — CF App Service OpenAPI Contract

## Context

CF App Service needs a stable CloudForge API contract before repository or Kubernetes reconciliation work begins.

The recommended MVP in `docs/cf-app-service.md` is a CloudForge abstraction over Kubernetes, initially implemented through CF-Provisioner. This task defines the REST contract under CF-Provisioner while preserving the option to extract a dedicated `cf-app-service` service later.

Reference:

- `docs/cf-app-service.md`
- `docs/rest-services-rules.md`
- `api/cf-provisioner/v1/openapi.yaml`
- `services/cf-router/internal/rest/proxy.go`

## Requirements

1. Extend `api/cf-provisioner/v1/openapi.yaml` with CF App Service schemas and routes.
2. Keep OpenAPI as the source of truth.
3. Add schemas for:
   - `AppService`
   - `CreateAppServiceRequest`
   - `AppServiceRuntime`
   - `AppServiceBuild`
   - `AppServiceResources`
   - `AppServiceEnvVar`
   - `AppServicePort`
   - `AppServiceExposure`
   - `AppServiceSwagger`
   - `AppServiceStatus`
   - `AppServiceList`
4. Add routes:
   - `POST /v1/networks/{networkId}/app-services`
   - `GET /v1/networks/{networkId}/app-services`
   - `GET /v1/app-services/{appServiceId}`
   - `DELETE /v1/app-services/{appServiceId}`
   - `POST /v1/app-services/{appServiceId}/exposure`
   - `DELETE /v1/app-services/{appServiceId}/exposure`
5. Add validation descriptions for:
   - active network required
   - subnet must exist and belong to the network
   - private subnet cannot be internet exposed
   - public subnet placement does not automatically mean public exposure
   - resource limits are required or defaulted
   - exposed port must reference a declared runtime port
6. Require public documentation metadata for every service exposed through Internet Gateway.

## Public Swagger Requirement

Every app service exposed through an internet gateway must have a publicly accessible Swagger page.

The OpenAPI contract must enforce this in the create/expose request:

- `exposure.type: InternetGateway` requires `swagger`.
- `swagger.specUrl` or `swagger.inlineSpec` is required for public HTTP/REST services.
- `swagger.publicPath` defaults to `/swagger/`.
- `swagger.openapiPath` defaults to `/openapi.json`.
- If a protocol cannot provide an OpenAPI document yet, internet gateway exposure must be rejected until a documentation adapter exists.

This is intentionally strict. Public CloudForge services must be self-describing.

## Acceptance Criteria

- OpenAPI validates.
- Public exposure schemas require Swagger/OpenAPI documentation metadata.
- API paths and operation IDs are stable and match repository naming conventions.
- Error responses use existing `Error` schema.
- Security remains internal-secret based for CF-Provisioner direct calls.
- CF-Router route table can route app-service paths through `/v1/networks`, `/v1/app-services`, and `/v1/jobs` without new public bypasses.
