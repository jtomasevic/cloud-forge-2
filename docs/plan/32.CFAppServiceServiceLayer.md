# Task 32 — CF App Service Service Layer

## Context

The service layer owns CF App Service business rules and orchestration. It validates tenant/network/subnet placement, coordinates repositories, creates async jobs, deploys workloads, and manages exposure state.

Reference:

- `services/cf-provisioner/internal/service/`
- `docs/rest-services-rules.md`
- `docs/cf-app-service.md`

## Requirements

1. Extend `ProvisionerService` with app-service methods:
   - `CreateAppService`
   - `GetAppService`
   - `ListAppServices`
   - `DeleteAppService`
   - `ExposeAppService`
   - `RemoveAppServiceExposure`
2. Add service-layer models separate from repository and REST models.
3. Validate:
   - network exists and is active
   - subnet exists and belongs to network
   - public exposure requires public subnet
   - private subnet exposure is rejected
   - resource values are valid
   - ports are valid and unique by name
   - exposure port references a declared port
   - public exposure includes Swagger metadata
4. Create async jobs for workload operations.
5. Coordinate:
   - app service repository
   - subnet repository
   - workload repository
   - gateway repository
   - Cilium repository
   - kubeconfig repository
6. Persist failure status and error message on failed jobs.
7. Make cleanup idempotent.
