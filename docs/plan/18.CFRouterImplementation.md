# Task 18 — CF-Router: Codegen, All Layers, main.go, and Dockerfile

## Context

CF-Router is the most focused of the three services — it validates credentials, calls CF-Accounts for tenant resolution, enriches the request, and reverse-proxies it to the correct upstream service. Because it is simpler than CF-Accounts and CF-Provisioner, this task covers everything in one pass: codegen, repository, service, REST, wiring, and Dockerfile.

Reference: `docs/cf-private-network.md` sections 5.3 (CF-Router position), 10.3 (request flow through the platform), 11.6 (BLAKE2b-256 for API key hashing), and 13.7 (all layer conventions).

## Dependencies

Tasks 1, 2, 4, 6, 10, 12, 17 must be complete. CF-Router depends on the CF-Accounts generated client (`libs/clients/cf-accounts`) for tenant resolution.

## Prompt

You are implementing the complete **CF-Router** service: codegen setup, all three layers, `main.go`, and Dockerfile.

## Part 3: Service Layer

### `internal/service/api.go`

```go
type RouterService interface {
    // ValidateAndResolve validates the incoming credentials and returns
    // the tenant context. It is called on every proxied request.
    ValidateAndResolve(ctx context.Context, params ValidateParams) (TenantContext, error)

    // Ready returns nil if CF-Router has a working connection to CF-Accounts.
    Ready(ctx context.Context) error
}

type Deps struct {
    APIKeys        apikeysrepo.APIKeyRepository
    AccountsClient cfaccountsclient.ClientWithResponsesInterface // generated CF-Accounts client
    JWTPublicKeyURL string // Keycloak JWKS URL for JWT verification
    InternalSecret  string // to add to proxied requests
}

func New(d Deps) RouterService {
    return &CFRouterService{deps: d}
}
```

### `internal/service/models.go`

```go
type AuthMethod string

const (
    AuthMethodJWT    AuthMethod = "jwt"
    AuthMethodAPIKey AuthMethod = "api_key"
)

type ValidateParams struct {
    AuthorizationHeader string // "Bearer <token>" or empty
    APIKeyHeader        string // raw API key from X-CF-API-Key header
}

type TenantContext struct {
    TenantID   string
    AccountID  string
    NetworkID  string
    Region     string
    Status     string
    ResolvedVia AuthMethod
}
```

### `internal/service/service.go`

Implement `CFRouterService`.

**ValidateAndResolve logic:**

```
If AuthorizationHeader starts with "Bearer ":
  1. Extract the JWT token
  2. Fetch Keycloak JWKS from JWTPublicKeyURL (cache the keys — refresh on key ID miss)
  3. Validate JWT signature, expiry, and issuer
  4. Extract account_id from the JWT claims (claim name: "cf_account_id" or "sub")
  5. Call CF-Accounts /internal/v1/resolve?accountId={account_id}
  6. Return TenantContext with ResolvedVia=jwt

Else if APIKeyHeader is not empty:
  1. Hash the raw API key with BLAKE2b-256
  2. Look up the hash in APIKeyRepository.GetByHash
  3. If found and not revoked: call CF-Accounts /internal/v1/resolve?accountId={accountID from record}
  4. Return TenantContext with ResolvedVia=api_key

Else:
  Return ErrUnauthenticated
```

**JWT verification:** Use only `crypto/rsa`, `encoding/json`, and `net/http` — no third-party JWT libraries. Parse the JWKS manually and verify RS256 signatures. If this is complex, use `golang.org/x/crypto` for any needed primitives. Document the decision clearly.

**BLAKE2b-256 hashing:**
```bash
cd services/cf-router && go get golang.org/x/crypto
```
```go
import "golang.org/x/crypto/blake2b"

func hashAPIKey(raw string) string {
    h, _ := blake2b.New256(nil)
    h.Write([]byte(raw))
    return hex.EncodeToString(h.Sum(nil))
}
```

## Part 4: REST Layer and Reverse Proxy

### `internal/rest/handler.go`

Implements the four spec operations (`Health`, `Ready`, `ListRoutes`, `ResolveTenantContext`) and the core reverse proxy logic.

### `internal/rest/proxy.go`

The most important piece of CF-Router. Implement the reverse proxy handler:

```go
// ProxyHandler handles all traffic that is not a CF-Router native endpoint.
// It validates credentials, resolves tenant context, injects headers, and
// proxies the request to the correct upstream.
func ProxyHandler(svc service.RouterService, routes RouteTable, internalSecret string) http.Handler
```

**ProxyHandler logic:**
1. Extract `Authorization` header and `X-CF-API-Key` header
2. Call `service.ValidateAndResolve` — return `401` on failure
3. Look up the target URL from `RouteTable` based on the request path prefix
4. Return `404` if no route matches
5. Clone the request, set the target URL
6. Inject headers: `X-CF-Tenant-ID`, `X-CF-Account-ID`, `X-CF-Network-ID`, `X-CF-Region`, `X-CF-Internal-Secret`
7. Remove `X-CF-API-Key` from the forwarded request (do not leak to upstream)
8. Use `httputil.ReverseProxy` for the actual proxying

**RouteTable:**
```go
type RouteEntry struct {
    PathPrefix  string
    TargetURL   string
    Description string
}

type RouteTable []RouteEntry

func (rt RouteTable) Match(path string) (RouteEntry, bool)
```

### `internal/rest/server.go`

Build `http.ServeMux`. CF-Router needs two kinds of routes:
1. Native endpoints (`/health`, `/ready`, `/internal/...`) → handled by the generated strict server
2. Everything else → handled by `ProxyHandler`

Use a catch-all pattern to route all non-native traffic to the proxy:
```go
mux.Handle("/", ProxyHandler(svc, routes, internalSecret))
mux.HandleFunc("GET /health", ...)
mux.HandleFunc("GET /ready", ...)
// etc.
```
