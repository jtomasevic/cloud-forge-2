# Task 28 — CF App Service Schema And Migrations

## Context

CF App Service needs durable records for service definitions, placement, exposure, runtime configuration, and async lifecycle state. This must be in place before repository and service layers can be implemented.

Reference:

- `docs/cf-app-service.md`
- `tools/migrations/migrations/`
- `services/cf-provisioner/internal/repository/jobs/`
- `services/cf-provisioner/internal/repository/subnets/`

## Requirements

1. Add ScyllaDB migrations for app service state.
2. Store enough data to reconstruct and reconcile an app service after process restart.
3. Support listing app services by network.
4. Support lookup by app service ID.
5. Support exposure status and Swagger documentation metadata.
6. Add app-service job types to provisioning jobs if app lifecycle is async.
7. Keep records tenant/network scoped.

## Suggested Tables

```sql
CREATE TABLE IF NOT EXISTS app_services (
  id uuid PRIMARY KEY,
  tenant_id uuid,
  network_id uuid,
  subnet_id uuid,
  name text,
  status text,
  image text,
  build_context text,
  dockerfile text,
  cpu text,
  memory text,
  env_json text,
  ports_json text,
  exposure_json text,
  swagger_json text,
  created_at timestamp,
  updated_at timestamp
);

CREATE TABLE IF NOT EXISTS app_services_by_network (
  network_id uuid,
  app_service_id uuid,
  name text,
  subnet_id uuid,
  status text,
  exposure_type text,
  created_at timestamp,
  PRIMARY KEY (network_id, app_service_id)
);
```

JSON columns are acceptable for MVP if documented. If the repo already has a stronger structured pattern by implementation time, prefer that pattern.

## Acceptance Criteria

- Migrations are idempotent.
- App service tables are created by `make dev-init`.
- Table names and columns are documented.
- Job types include:
  - `create_app_service`
  - `delete_app_service`
  - `expose_app_service`
  - `remove_app_service_exposure`
