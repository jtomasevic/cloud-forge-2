# Task 4 — OpenBao Client Library

## Context

`libs/openbao` provides a reusable client for OpenBao (the open-source Vault fork). It is used by CF-Provisioner to store and retrieve tenant kubeconfigs, and by CF-Router/CF-Accounts to store and verify API secrets. The client must support reading, writing, deleting, and listing secrets at arbitrary paths.

Reference: `docs/cf-private-network.md` section 11.4 (OpenBao validation) and the control-plane access revocation flow in section 10.5.

## Dependencies

Task 1 (repository skeleton) and Task 2 (cloudforge-core) must be complete.

### Package: `pkg/client`

File: `libs/openbao/pkg/client/client.go`

**Config:**
```go
type Config struct {
    Address string // e.g. "http://localhost:8200"
    Token   string // root or service token
}
```

**Client interface:**

Define a `SecretsClient` interface (so it can be mocked in tests):

```go
type SecretsClient interface {
    // Write stores data at the given path. data is a map of key-value pairs.
    Write(ctx context.Context, path string, data map[string]interface{}) error

    // Read retrieves data at the given path. Returns ErrSecretNotFound if
    // the path does not exist.
    Read(ctx context.Context, path string) (map[string]interface{}, error)

    // Delete permanently removes the secret at the given path.
    Delete(ctx context.Context, path string) error

    // List returns the keys available at the given path prefix.
    List(ctx context.Context, pathPrefix string) ([]string, error)
}
```

**CFSecretsClient** — concrete implementation:

- `New(cfg Config) (SecretsClient, error)` — creates a configured Vault/OpenBao client. Returns `ErrClientInit` if the address is invalid.
- All methods wrap Vault API errors into typed `CFError` values:
  - `404 / nil secret` → `ErrSecretNotFound`
  - `403` → `cferrors.ErrForbidden`
  - network / connection errors → `cferrors.ErrUnavailable`
  - all others → `cferrors.ErrInternal`
- The client must respect the provided `context.Context` for cancellation.

File: `libs/openbao/pkg/client/errors.go`

```go
var (
    ErrSecretNotFound = cferrors.New(cferrors.CodeNotFound, "secret not found")
    ErrClientInit     = cferrors.New(cferrors.CodeInternal, "openbao client initialization failed")
)
```

### Kubeconfig helper

File: `libs/openbao/pkg/client/kubeconfig.go`

Provide two convenience functions used by CF-Provisioner:

```go
// StoreKubeconfig stores a tenant kubeconfig at the canonical path.
// Path: "secret/tenants/{tenantID}/kubeconfig"
// The kubeconfig bytes are base64-encoded and stored as the "data" key.
func StoreKubeconfig(ctx context.Context, c SecretsClient, tenantID string, kubeconfigBytes []byte) error

// LoadKubeconfig retrieves a tenant kubeconfig from the canonical path.
// Returns ErrSecretNotFound if the kubeconfig has been revoked or never stored.
func LoadKubeconfig(ctx context.Context, c SecretsClient, tenantID string) ([]byte, error)

// RevokeKubeconfig deletes the kubeconfig from OpenBao, immediately
// removing control-plane management access to that tenant environment.
func RevokeKubeconfig(ctx context.Context, c SecretsClient, tenantID string) error
```

The canonical path prefix is `secret/tenants/`. This is a `kv` v1 mount. Document this assumption in the function comments.

### Tests

Write unit tests using a mock `SecretsClient` (implement a simple `mockSecretsClient` struct that satisfies the interface):
- `StoreKubeconfig` calls `Write` with the correct path and base64-encoded data
- `LoadKubeconfig` decodes the base64 data returned by `Read`
- `RevokeKubeconfig` calls `Delete` with the correct path
- `LoadKubeconfig` returns `ErrSecretNotFound` when `Read` returns `ErrSecretNotFound`

Tag any tests requiring a live OpenBao instance with `//go:build integration`.
