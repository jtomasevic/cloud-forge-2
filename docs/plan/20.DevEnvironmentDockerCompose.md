# Task 20 — Dev Environment: Docker Compose (ScyllaDB, OpenBao, Keycloak)

## Context

The backing services (ScyllaDB, OpenBao, Keycloak) run in Docker Compose for local development. They are not deployed into k3d — they run alongside it on the host via Docker. This keeps them simple, fast to start, and easy to reset.

Reference: `docs/cf-private-network.md` section 12.3 (what should be real vs mocked in dev).

## Dependencies

Task 1 must be complete. Docker and Docker Compose must be installed.

## Prompt

### Keycloak dev realm export

File: `dev/keycloak/realm-export.json`

Create a minimal Keycloak realm export that seeds the development environment. The realm must contain:

**Realm name:** `cloudforge`

**Clients:**
- `cf-console` — public client for the CloudForge web console (OIDC, authorization code flow)
- `cf-internal` — confidential client for service-to-service OIDC (for future use)

**Users:**
- `dev-user@cloudforge.io` / password `devpassword` — a regular tenant user
- `admin@cloudforge.io` / password `adminpassword` — a platform admin

**Realm settings:**
- Access token lifespan: 300 seconds (5 minutes)
- Refresh token lifespan: 1800 seconds (30 minutes)

Create the JSON by exporting from a running Keycloak instance, or write it by hand following the Keycloak realm export format. The JSON must include `realm`, `clients`, `users`, and `credentials` sections.

If generating by hand is impractical, provide a `dev/keycloak/README.md` with instructions for:
```
1. Start Keycloak without the import: docker compose up keycloak
2. Go to http://localhost:8084/auth/admin (admin/admin)
3. Create realm "cloudforge"
4. Create the clients and users above
5. Export the realm: Admin > Realm Settings > Export
6. Save to dev/keycloak/realm-export.json
```

### OpenBao initialization script

File: `dev/scripts/init-openbao.sh`

OpenBao in dev mode starts with a pre-configured root token and in-memory storage. The KV secrets engine needs to be enabled at the `secret/` path.

```bash
#!/usr/bin/env bash
set -euo pipefail

VAULT_ADDR="${VAULT_ADDR:-http://localhost:8200}"
VAULT_TOKEN="${VAULT_TOKEN:-dev-root-token}"

export VAULT_ADDR VAULT_TOKEN

echo "Initializing OpenBao..."

# Enable KV v1 secrets engine at secret/
vault secrets enable -path=secret kv 2>/dev/null || echo "KV secrets engine already enabled"

# Create an initial policy for CF-Provisioner
vault policy write cf-provisioner - <<EOF
path "secret/tenants/*" {
  capabilities = ["create", "read", "update", "delete", "list"]
}
EOF

echo "OpenBao initialized"
```

### ScyllaDB wait-and-migrate script

File: `dev/scripts/init-scylladb.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

MAX_RETRIES=30
RETRY_INTERVAL=3

echo "Waiting for ScyllaDB to be ready..."
for i in $(seq 1 $MAX_RETRIES); do
    if cqlsh localhost 9042 -e "describe keyspaces" &>/dev/null; then
        echo "ScyllaDB is ready"
        break
    fi
    echo "  Attempt ${i}/${MAX_RETRIES} — waiting ${RETRY_INTERVAL}s..."
    sleep $RETRY_INTERVAL
done

echo "Running schema migrations..."
cd "$(git rev-parse --show-toplevel)"
go run ./tools/migrations/... -hosts localhost:9042 -keyspace cloudforge

echo "Schema migrations complete"
```

### Makefile targets

Add the following targets to the root `Makefile`:

```makefile
.PHONY: dev-up dev-down dev-init dev-reset

dev-up:
	docker compose -f dev/docker-compose.yml up -d
	@echo "Backing services started. Run 'make dev-init' to seed data."

dev-down:
	docker compose -f dev/docker-compose.yml down

dev-init: dev-up
	@echo "Waiting for services to be ready..."
	@sleep 5
	dev/scripts/init-openbao.sh
	dev/scripts/init-scylladb.sh
	@echo "Dev environment initialized"

dev-reset: dev-down
	docker compose -f dev/docker-compose.yml down -v
	@echo "Dev environment reset (all data deleted)"
```

## Acceptance Criteria

- `make dev-up` starts all three services without errors
- `cqlsh localhost 9042 -e 'describe keyspaces'` succeeds after `make dev-init`
- `curl http://localhost:8200/v1/sys/health` returns `{"initialized":true,...}`
- `curl http://localhost:8084/health/ready` returns healthy
- `make dev-reset` removes all data volumes
- `make dev-init` is idempotent (safe to run twice)
- Keycloak dev realm `cloudforge` is created with the two test users
