# Task 33 — CF App Service REST Layer And Router Integration

## Context

After service-layer behavior is implemented, expose CF App Service through CF-Provisioner REST handlers and CF-Router routing.

Reference:

- `services/cf-provisioner/internal/rest/`
- `services/cf-router/internal/rest/proxy.go`
- `services/cf-router/internal/rest/swagger.go`
- `docs/rest-services-rules.md`

## Requirements

1. Implement CF-Provisioner REST handlers for app-service operations.
2. Keep REST DTOs separate from service-layer models.
3. Add explicit transform functions:
   - REST request -> service params
   - service model -> REST response
4. Map service errors to correct HTTP statuses.
5. Ensure CF-Router forwards:
   - `/v1/networks/{networkId}/app-services`
   - `/v1/app-services/{appServiceId}`
6. Ensure no app-service route becomes public/auth-bypassed.
7. Update aggregated Swagger/OpenAPI output so the CloudForge public API docs include app-service APIs.

## Acceptance Criteria

- App-service REST handlers compile and are covered by tests.
- CF-Router forwards app-service routes to CF-Provisioner.
- Public signup/login bypass remains the only app-relevant public bypass.
- Aggregated Swagger includes app-service endpoints.
- Error responses use standard CloudForge error shape.
