# Task 29 — CF App Service State Repository Layer

## Context

After schema migration, CF-Provisioner needs a repository package for durable CF App Service records. This package owns ScyllaDB access only. It must not create Kubernetes workloads or Gateway API routes.

Reference:

- `services/cf-provisioner/internal/repository/cidr/`
- `services/cf-provisioner/internal/repository/jobs/`
- `docs/rest-services-rules.md`

## Requirements

1. Add `services/cf-provisioner/internal/repository/appservices/`.
2. Implement create, get, list-by-network, update-status, update-exposure, and delete/mark-deleted operations.
3. Keep repository models separate from service-layer models.
4. Preserve ScyllaDB denormalized table consistency where possible.
5. Map repository errors to typed package errors:
   - `ErrAppServiceNotFound`
   - `ErrAppServiceExists`
   - `ErrInvalidAppService`
6. Store Swagger documentation metadata for public services.
7. Do not perform tenant authorization in this repository package.

## Code Comments And READMEs

- Add a package comment in `api.go` explaining this package owns persistent app service records.
- Comment every denormalized write path.
- Add `README.md` covering:
  - package purpose
  - table ownership
  - public Swagger metadata storage
  - status and exposure update flow
  - what the package deliberately does not do

## Acceptance Criteria

- Repository unit tests cover create/get/list/update/delete paths.
- JSON serialization of runtime/exposure/swagger fields is tested.
- Not-found and duplicate behavior are covered.
- Repository code does not import REST or service packages.
- CF-Provisioner `main.go` can wire the repository through deps in later tasks.
