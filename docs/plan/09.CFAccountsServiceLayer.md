# Task 9 — CF-Accounts Service Layer

## Context

The service layer contains all business logic for CF-Accounts. It orchestrates the four repository packages, enforces business rules (e.g. duplicate slug prevention, credential generation), and exposes a typed interface consumed by the REST layer above it.

The service layer never imports REST models or REST errors. It uses `libs/cloudforge-core` domain types where possible and defines its own service-layer models for everything else.

Reference: `docs/cf-private-network.md` sections 5.3 (CF-Accounts responsibilities) and 13.7 (service layer file conventions). Also `docs/rest-services-rules.md` (service layer rules and naming convention).

## Dependencies

Tasks 2, 8 must be complete. Task 6 (codegen) must be complete to understand the operations that need to be served.

## Prompt

You are implementing the service layer for **CF-Accounts** in `services/cf-accounts/internal/service/`.

### Architecture rules (mandatory):
- The service interface is defined in `api.go`
- The concrete struct is named `CFAccountsService` — never exported directly; always returned as the interface type from `New()`
- Service models are in `models.go` — these are independent of REST and repository models
- Transform methods to/from repository models are in `models_transform.go`
- Typed errors are in `errors.go`
- Business logic only in `service.go` — no HTTP concepts, no CQL queries

### `internal/service/api.go`

Define the `AccountsService` interface. Every method corresponds to one or more REST operations:

```go
type AccountsService interface {
    // Account operations
    CreateAccount(ctx context.Context, params CreateAccountParams) (Account, error)
    GetAccount(ctx context.Context, id string) (Account, error)
    GetAccountByEmail(ctx context.Context, email string) (Account, error)
    ListAccounts(ctx context.Context, limit, offset int) ([]Account, int, error)
    SuspendAccount(ctx context.Context, id string) error

    // Tenant operations
    GetTenant(ctx context.Context, id string) (Tenant, error)
    ListTenants(ctx context.Context, accountID string, limit, offset int) ([]Tenant, error)

    // Network operations
    CreateNetwork(ctx context.Context, params CreateNetworkParams) (Network, error)
    GetNetwork(ctx context.Context, id string) (Network, error)
    ListNetworks(ctx context.Context, tenantID string) ([]Network, error)
    DeprovisionNetwork(ctx context.Context, id string) error

    // Credential operations
    CreateCredential(ctx context.Context, params CreateCredentialParams) (CredentialCreated, error)
    ListCredentials(ctx context.Context, accountID string) ([]CredentialMeta, error)
    RevokeCredential(ctx context.Context, id string) error

    // Internal: used by CF-Router for tenant resolution
    ResolveTenantContext(ctx context.Context, params ResolveTenantParams) (TenantContext, error)
}

type Deps struct {
    Accounts    accountsrepo.AccountsRepository
    Tenants     tenantsrepo.TenantsRepository
    Networks    networksrepo.NetworksRepository
    Credentials credentialsrepo.CredentialsRepository
}

func New(d Deps) AccountsService {
    return &CFAccountsService{deps: d}
}
```

### `internal/service/service.go`

Implement `CFAccountsService`. Key business rules to enforce:

**CreateAccount:**
1. Check if email already exists via `Accounts.GetByEmail` — return `ErrAccountEmailTaken` if found
2. Generate a new UUID for the account ID
3. Set `status = "active"`, `created_at = now`, `updated_at = now`
4. Insert into repository
5. Also create a default `Tenant` for this account:
   - Generate a slug from the email local part (strip domain, lowercase, replace non-alphanumeric with `-`, truncate to 63 chars)
   - If slug conflicts, append a random 4-char hex suffix
   - Insert tenant into repository with `status = "provisioning"`
6. Return the created Account

**CreateCredential:**
1. Generate a cryptographically random 32-byte API key using `crypto/rand`
2. Encode as URL-safe base64 → this is the `secret` returned once to the caller
3. Hash it with BLAKE2b-256: `golang.org/x/crypto/blake2b` (see dependency note below)
4. Store only the hash in the repository
5. The key prefix is the first 8 characters of the base64-encoded key
6. Return `CredentialCreated{..., Secret: rawKey}`

**ResolveTenantContext:**
- If `APIKeyHash` is provided: look up `Credentials.GetByHash`, check not revoked, get account, get tenant
- If `AccountID` is provided: get account, get tenant by account, get active network
- Return `TenantContext`

**DeprovisionNetwork:**
- Update network status to `"deprovisioning"` — do not delete the record
- The actual infrastructure teardown is CF-Provisioner's job; CF-Accounts only manages state

### `internal/service/errors.go`

```go
var (
    ErrAccountNotFound    = cferrors.New(cferrors.CodeNotFound, "account not found")
    ErrAccountEmailTaken  = cferrors.New(cferrors.CodeAlreadyExists, "email already registered")
    ErrTenantNotFound     = cferrors.New(cferrors.CodeNotFound, "tenant not found")
    ErrNetworkNotFound    = cferrors.New(cferrors.CodeNotFound, "network not found")
    ErrCredentialNotFound = cferrors.New(cferrors.CodeNotFound, "credential not found")
    ErrCredentialRevoked  = cferrors.New(cferrors.CodeForbidden, "API key has been revoked")
    ErrSlugConflict       = cferrors.New(cferrors.CodeConflict, "tenant slug conflict")
    ErrResolutionFailed   = cferrors.New(cferrors.CodeUnauthorized, "cannot resolve tenant from provided credentials")
)
```
