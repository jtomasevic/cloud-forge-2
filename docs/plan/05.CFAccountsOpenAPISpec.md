# Task 5 — CF-Accounts OpenAPI Spec

## Context

Before writing a single handler, the CF-Accounts HTTP contract must be defined as an OpenAPI 3.0.3 specification. This spec is the source of truth: server stubs and the client SDK are generated from it. Any change to the HTTP contract must start here.

CF-Accounts is the authoritative registry for: customer accounts, tenant identities, private networks, API credentials, and provisioned service bindings. Its API is consumed by CF-Router (tenant resolution) and by end users/operators via the CloudForge API.

Reference: `docs/cf-private-network.md` sections 5.2 (responsibility split), 8.3 (what is created during onboarding), 13.2 (OpenAPI contract rule), and 13.4 (codegen conventions).

## Dependencies

Task 1 (repository skeleton) must be complete.

## Prompt

You are writing the OpenAPI 3.0.3 specification for **CF-Accounts**, the account and tenant registry service of CloudForge.

### Output file: `api/cf-accounts/v1/openapi.yaml`

Write a complete, valid OpenAPI 3.0.3 specification. Do not use stubs or placeholders — every operation must have full request/response schemas, meaningful descriptions, and correct status codes.

### Security schemes

Define two security schemes:
1. `BearerAuth` — JWT bearer token (issued by Keycloak)
2. `ApiKeyAuth` — custom header `X-CF-API-Key`

Apply `BearerAuth` as the default security requirement on all operations unless otherwise noted.

### Operations to define

#### Accounts

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/accounts` | Create a new customer account |
| `GET` | `/v1/accounts/{accountId}` | Get account by ID |
| `GET` | `/v1/accounts` | List accounts (paginated, query params: `limit`, `offset`) |
| `DELETE` | `/v1/accounts/{accountId}` | Suspend/delete an account |

#### Tenants

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/accounts/{accountId}/tenants` | List tenants for an account |
| `GET` | `/v1/tenants/{tenantId}` | Get tenant by ID |

#### Private Networks

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/tenants/{tenantId}/networks` | Create a private network for a tenant |
| `GET` | `/v1/tenants/{tenantId}/networks` | List networks for a tenant |
| `GET` | `/v1/networks/{networkId}` | Get network by ID |
| `DELETE` | `/v1/networks/{networkId}` | Deprovision a network |

#### API Credentials

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/accounts/{accountId}/credentials` | Create an API key pair |
| `GET` | `/v1/accounts/{accountId}/credentials` | List credential metadata (never returns raw secret) |
| `DELETE` | `/v1/accounts/{accountId}/credentials/{keyId}` | Revoke an API key |

#### Internal — Tenant Resolution (used by CF-Router)

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/internal/v1/resolve` | Resolve tenant context from account ID or API key hash |

This internal endpoint is not protected by `BearerAuth` — it uses a shared internal secret header `X-CF-Internal-Secret`. Document this in the spec.

### Status codes

Use correct HTTP status codes:
- `POST` create operations: `201 Created`
- `GET` operations: `200 OK`
- `DELETE` operations: `204 No Content`
- `400 Bad Request` for validation failures
- `401 Unauthorized` for missing/invalid credentials
- `403 Forbidden` for insufficient permissions
- `404 Not Found` for unknown IDs
- `409 Conflict` for duplicate slug/email
- `500 Internal Server Error` for unexpected failures

All error responses use the `Error` schema.

---

### Pagination

For list operations, use query parameters `limit` (default 20, max 100) and `offset` (default 0). Response envelopes include:
```yaml
items: array
total: integer
limit: integer
offset: integer
```
