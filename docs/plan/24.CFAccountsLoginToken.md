# Task: CF-Accounts Login Returns Access Token

## Problem

`POST /v1/auth/login` already exists, but it currently verifies the local
`accounts.password_hash` and returns an `Account`.

After the signup workflow moved identity creation into Keycloak, the useful
login contract is different:

- clients need a Keycloak access token they can put into `Authorization: Bearer`
- CF-Router needs that token to contain `cf_account_id`
- local Swagger should be able to log in without calling Keycloak directly
- password validation must not become a second independent auth system

The login endpoint should authenticate against Keycloak and return a token
response owned by the CF-Accounts HTTP contract.

## Architecture Rules

Follow `docs/rest-services-rules.md` strictly:

- update `api/cf-accounts/v1/openapi.yaml` before code
- regenerate server stubs and clients; do not hand-edit generated files
- keep REST, service, and external API models separate
- keep each layer's typed errors in that layer
- cross layer boundaries only through explicit transform functions
- use only Go standard library for HTTP/client code; no web framework or OAuth
  helper library

## Proposed Contract

Keep the existing route:

```http
POST /v1/auth/login
```

Request stays:

```json
{
  "email": "user@example.com",
  "password": "longpassword1"
}
```

Change `200` response from `Account` to a new schema, for example:

```json
{
  "accessToken": "<jwt>",
  "tokenType": "Bearer",
  "expiresIn": 300,
  "refreshToken": "<optional-refresh-token>",
  "refreshExpiresIn": 1800,
  "idToken": "<optional-id-token>",
  "scope": "openid profile email",
  "account": {
    "id": "222e9117-3fed-4915-b591-5f524f1fe158",
    "email": "user@example.com",
    "status": "active",
    "createdAt": "2026-06-08T20:49:03Z"
  }
}
```

Notes:

- `accessToken`, `tokenType`, `expiresIn`, and `account` should be required.
- `refreshToken`, `refreshExpiresIn`, `idToken`, and `scope` can be optional
  because Keycloak client settings may vary by environment.
- `401` must remain generic for bad email/password, unknown user, disabled
  Keycloak user, missing `cf_account_id`, inactive CF account, or account/token
  mismatch.
- Do not return raw Keycloak error bodies to clients.

## Implementation Plan

Update `api/cf-accounts/v1/openapi.yaml`:

- add token fields with clear sensitivity descriptions
- change `/v1/auth/login` `200` response from `Account` to `LoginResponse`
- keep `security: []`
- keep `400`, `401`, and `500` responses
- document that the token is issued by Keycloak and includes `cf_account_id`


This should refresh:

- `services/cf-accounts/internal/rest/generated/server.gen.go`
- `libs/clients/cf-accounts/v1/client.gen.go`
- any aggregated/generated client files touched by the workspace generator

### 2. External API Layer: Identity Provider

Extend `services/cf-accounts/internal/repository/identity/`.

Add layer-specific models in `api.go` or `models.go`:

- `AuthenticatePasswordParams`
- `TokenSet`

Example shape:

```go
type AuthenticatePasswordParams struct {
    Email    string
    Password string
}

type TokenSet struct {
    AccessToken      string
    RefreshToken     string
    IDToken          string
    TokenType        string
    Scope            string
    ExpiresIn        int
    RefreshExpiresIn int
    AccountID        string
    Subject          string
    Email            string
}
```

Add identity-layer typed errors in `errors.go`:

- `ErrAuthenticationFailed`
- reuse `ErrClientConfig`
- reuse `ErrIdentityService`

Extend `Provider`:

```go
AuthenticatePassword(ctx context.Context, params AuthenticatePasswordParams) (TokenSet, error)
```

Update `KeycloakProvider`:

- call realm token endpoint:
  `/realms/{KEYCLOAK_REALM}/protocol/openid-connect/token`
- use a login client separate from admin credentials:
  - `KEYCLOAK_LOGIN_CLIENT_ID`, default `cf-console`
  - `KEYCLOAK_LOGIN_CLIENT_SECRET`, optional
- send `grant_type=password`, `client_id`, `username`, `password`, and optional
  `client_secret`
- map Keycloak `400 invalid_grant` to identity `ErrAuthenticationFailed`
- map other 4xx/5xx to identity `ErrIdentityService`
- parse token JSON with `encoding/json`
- decode the access token payload with `encoding/base64` to extract:
  - `cf_account_id`
  - `sub`
  - `email`
- return `ErrAuthenticationFailed` if `access_token` or `cf_account_id` is
  missing

Do not leak raw Keycloak response structs above this repository package.

### 3. Service Layer

Update `services/cf-accounts/internal/service/`.

Add service models:

- keep `LoginWithPasswordParams`
- add `LoginResult`

Example:

```go
type LoginResult struct {
    AccessToken      string
    RefreshToken     string
    IDToken          string
    TokenType        string
    Scope            string
    ExpiresIn        int
    RefreshExpiresIn int
    Account          Account
}
```

Change `AccountsService.LoginWithPassword` to return `LoginResult` instead of
`Account`.

Business flow:

1. Trim email and validate password shape as today.
2. Require `deps.Identity`; missing identity provider is an internal
   configuration error.
3. Call `Identity.AuthenticatePassword`.
4. Map `identity.ErrAuthenticationFailed` to service `ErrInvalidCredentials`.
5. Load account by `TokenSet.AccountID`.
6. Require account status `active`.
7. Require the token `cf_account_id` to match the loaded account ID.
8. If token email is present, require it to match account email case
   insensitively.
9. Return `LoginResult`.

Important behavior decision:

- Do not verify the local bcrypt hash for token login.
- Keycloak is the password source of truth for this endpoint.
- The current DB `password_hash` can remain for migration/backward
  compatibility, but token login must not depend on two separate password
  stores.

### 4. REST Layer

Update `services/cf-accounts/internal/rest/`.

- Keep handler method name `LoginWithPassword` because OpenAPI operationId can
  remain stable.
- Use `ToServiceLoginWithPasswordParams` as today.
- Add `ToLoginResponseFromServiceLoginResult`.
- Return `generated.LoginWithPassword200JSONResponse(...)` with the generated
  `LoginResponse`.
- Update REST tests for:
  - request transform
  - response transform
  - 400 for malformed body
  - 401 for service `ErrInvalidCredentials`

Do not create service params inline in the handler.

### 5. CF-Router Public Proxy Path

Update CF-Router so clients can log in through the same public API gateway path.

Changes:

- add `/v1/auth` to `DefaultRouteTable` with target CF-Accounts
- treat only `POST /v1/auth/login` as public, same as `POST /v1/accounts`
- strip all trusted `X-CF-*` headers and `X-CF-API-Key` before forwarding
- do not inject tenant headers or internal secret for public login
- keep all other `/v1/auth/*` routes non-public unless explicitly added later

Tests:

- `POST /v1/auth/login` is proxied without auth
- client-supplied `X-CF-Internal-Secret`, `X-CF-Tenant-ID`,
  `X-CF-Account-ID`, and `X-CF-API-Key` are stripped
- non-login `/v1/auth/...` still requires auth or returns expected error

### 7. Tests

Add or update focused tests:

Identity repository:

- successful Keycloak token response maps to `TokenSet`
- `invalid_grant` maps to `identity.ErrAuthenticationFailed`
- missing `access_token` maps to `identity.ErrIdentityService`
- access token missing `cf_account_id` maps to `identity.ErrAuthenticationFailed`

Service:

- successful login calls identity provider and returns token result

- token account ID mismatch maps to `ErrInvalidCredentials`

REST:

- invalid request returns 400
- bad credentials returns 401

Router:

- public login proxy works without auth
- public login strips trusted headers

## Acceptance Criteria

- `POST /v1/auth/login` returns a Keycloak access token response, not just an
  account object.
- Returned access token contains `cf_account_id`.
- The endpoint works through CF-Router/Envoy without prior authorization.
- Wrong credentials return generic 401.
- Raw Keycloak errors and raw repository models do not leak through service or
  REST layers.
- Tests cover identity, service, REST, and router behavior.
- Docs and smoke scripts show login through CloudForge API, not direct Keycloak
  calls.

## Out Of Scope

- Refresh-token endpoint.
- Logout/revoke session endpoint.
- MFA, email verification, CAPTCHA, and rate limiting.
- Removing `accounts.password_hash`; that should be a separate migration plan.
- Changing Keycloak realm security policy beyond the existing direct-access
  grant used for local/dev login.
