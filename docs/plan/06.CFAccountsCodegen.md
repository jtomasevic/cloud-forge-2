# Task 6 — CF-Accounts Codegen

## Context

With the CF-Accounts OpenAPI spec written, this task configures `oapi-codegen` and runs it to produce:
1. Server stubs into `services/cf-accounts/internal/rest/generated/`
2. A typed client library into `libs/clients/cf-accounts/v1/`

These generated files must never be hand-edited. All subsequent handler code implements the generated `StrictServerInterface`.

Reference: `docs/cf-private-network.md` sections 13.3 (oapi-codegen), 13.4 (codegen conventions), and 13.5 (generated client libraries).

## Dependencies

Tasks 1 and 5 must be complete (repository skeleton + CF-Accounts OpenAPI spec).

## Prompt

You are configuring and running code generation for **CF-Accounts** using `oapi-codegen v2`.

### Tool: `oapi-codegen v2`

Install if not present:
```bash
go install github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@latest
```

---

### Server stub configuration

File: `api/cf-accounts/v1/oapi-server.cfg.yaml`

```yaml
package: generated
generate:
  strict-server: true
  models: true
  embedded-spec: true
output: ../../../services/cf-accounts/internal/rest/generated/server.gen.go
output-options:
  skip-fmt: false
```

The `strict-server: true` option generates a `StrictServerInterface` where every operation is a function that receives a typed params struct and returns a typed response struct. This enforces at compile time that every operation is implemented.

### Client library configuration

File: `api/cf-accounts/v1/oapi-client.cfg.yaml`

```yaml
package: cfaccountsclient
generate:
  client: true
  models: true
output: ../../../libs/clients/cf-accounts/v1/client.gen.go
```

---

### Running codegen

Run both generators from the repository root:

```bash
oapi-codegen -config api/cf-accounts/v1/oapi-server.cfg.yaml api/cf-accounts/v1/openapi.yaml
oapi-codegen -config api/cf-accounts/v1/oapi-client.cfg.yaml api/cf-accounts/v1/openapi.yaml
```

Verify both output files are created:
- `services/cf-accounts/internal/rest/generated/server.gen.go`
- `libs/clients/cf-accounts/v1/client.gen.go`

---

### go:generate directive

Add a `generate.go` file at the module root for CF-Accounts:

File: `services/cf-accounts/generate.go`

```go
package main

//go:generate oapi-codegen -config ../../api/cf-accounts/v1/oapi-server.cfg.yaml ../../api/cf-accounts/v1/openapi.yaml
//go:generate oapi-codegen -config ../../api/cf-accounts/v1/oapi-client.cfg.yaml ../../api/cf-accounts/v1/openapi.yaml
```

---

### Update go.mod for the generated server stub

The generated `server.gen.go` will import `oapi-codegen` runtime packages. Add the required dependency to `services/cf-accounts/go.mod`:

```bash
cd services/cf-accounts && go get github.com/oapi-codegen/runtime
```

### Update go.mod for the generated client library

File: `libs/clients/cf-accounts/go.mod` — add:
```bash
cd libs/clients/cf-accounts && go get github.com/oapi-codegen/runtime
```

---

### Verify compilation

After codegen runs:

```bash
cd services/cf-accounts && go build ./...
cd libs/clients/cf-accounts && go build ./...
```

Both must compile. At this stage, the `StrictServerInterface` is defined but not yet implemented — this is expected. The build will fail with "interface not implemented" errors only when `main.go` tries to wire the server. That wiring happens in Task 10.

To verify compilation without wiring errors, confirm that `go build ./internal/rest/generated/` compiles on its own.

## Acceptance Criteria

- `services/cf-accounts/internal/rest/generated/server.gen.go` exists and contains the `StrictServerInterface`
- `libs/clients/cf-accounts/v1/client.gen.go` exists and contains a typed HTTP client
- Both files compile with `go build`
- Neither file is hand-edited (contains the oapi-codegen header comment)
- `go generate ./...` from `services/cf-accounts/` regenerates both files cleanly
