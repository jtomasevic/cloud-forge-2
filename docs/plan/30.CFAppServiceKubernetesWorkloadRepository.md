# Task 30 — CF App Service Kubernetes Workload Repository

## Context

CF App Service must map user-facing runtime definitions to Kubernetes workload objects inside the tenant private network boundary. This task adds the infrastructure repository that creates Kubernetes Deployments and Services.

Reference:

- `docs/cf-app-service.md` section 8
- `services/cf-provisioner/internal/repository/vcluster/`
- `services/cf-provisioner/internal/repository/gateway/`
- `services/cf-provisioner/internal/repository/cilium/`

## Requirements

1. Add a workload repository package under CF-Provisioner.
2. Use tenant vCluster kubeconfig when creating app workloads.
3. Create Kubernetes Deployment for networked and worker services.
4. Create Kubernetes Service only when runtime ports are declared.
5. Apply labels for:
   - tenant ID
   - network ID
   - subnet ID
   - app service ID
   - visibility (`private` or `public`)
6. Apply CPU and memory requests/limits.
7. Apply environment variables.
8. Support one container per app service in MVP.
9. Report readiness/status from Deployment conditions.
10. Delete Deployment and Service during app service deletion.

## Implementation Notes

Suggested interface:

```go
type WorkloadClient interface {
    Apply(ctx context.Context, params ApplyWorkloadParams) (WorkloadInfo, error)
    Get(ctx context.Context, namespace, name string) (WorkloadInfo, error)
    Delete(ctx context.Context, namespace, name string) error
}
```

The repository should use Kubernetes clients, not shelling out to `kubectl`.
