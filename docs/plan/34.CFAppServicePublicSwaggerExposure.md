# Task 34 — Public Swagger Exposure For Internet Gateway App Services

## Context

Every publicly exposed CF App Service must have a publicly accessible Swagger page. This is a platform rule, not a best-effort documentation feature.

When a user exposes an app service via Internet Gateway, CloudForge must expose:

- application traffic
- Swagger UI
- OpenAPI JSON

If Swagger/OpenAPI metadata is missing, public exposure must be rejected.

Reference:

- `docs/cf-app-service.md`
- `services/cf-router/internal/rest/swagger.go`
- `dev/k8s/gateway/httproute-cf-router.yaml`
- `services/cf-provisioner/internal/repository/gateway/`

## Requirements

1. Add app-service Swagger metadata to API and service models if not already present.
2. Enforce Swagger metadata for `exposure.type: InternetGateway`.
3. Support a public Swagger UI path per exposed app service.
4. Support a public OpenAPI JSON path per exposed app service.
5. Decide one implementation model:
   - app service serves its own Swagger UI and OpenAPI JSON, or
   - CloudForge serves Swagger UI and proxies/fetches the app OpenAPI JSON, or
   - CloudForge stores the OpenAPI document and serves it through a docs adapter.
6. For MVP, prefer the simplest reliable model:
   - app service provides OpenAPI JSON
   - CloudForge provides reusable Swagger UI route if app service does not
7. Ensure public docs routes use the same internet gateway hostname as the app service.
8. Ensure private services do not get public Swagger routes.

## Required User-Facing Behavior

For an exposed app service:

```text
https://orders.example.cloudforge.dev/swagger/
https://orders.example.cloudforge.dev/openapi.json
```

In local development:

```text
http://orders.local.cloudforge.dev:18080/swagger/
http://orders.local.cloudforge.dev:18080/openapi.json
```

## Code Comments And READMEs

- Comment why public exposure is rejected without Swagger metadata.
- Document the chosen docs-serving model in package READMEs.
- Add README content for any docs adapter package explaining:
  - whether it proxies, stores, or renders docs
  - security assumptions
  - route construction

## Acceptance Criteria

- Internet gateway exposure without Swagger/OpenAPI metadata returns a validation error.
- Public HTTP/REST app service exposes a working Swagger page.
- Public OpenAPI JSON is reachable.
- Private app service does not expose Swagger publicly.
- Tests cover validation and route creation.

## Validation

```bash

```

Then verify locally with a public example app:

```bash
curl -sf http://orders.local.cloudforge.dev:18080/openapi.json
curl -sf http://orders.local.cloudforge.dev:18080/swagger/
```
