# Task 36 — CF App Service gRPC And TCP Gateway Support

## Context

`docs/cf-app-service.md` section 5.5 calls out a current limitation:

- Gateway API support is currently HTTPRoute only.

The MVP can start with HTTP/REST, but CF App Service is intended to support gRPC and TCP services. This task expands route support after HTTP app services are stable.

Reference:

- `services/cf-provisioner/internal/repository/gateway/`
- `api/cf-provisioner/v1/openapi.yaml`
- Gateway API `GRPCRoute` and `TCPRoute`

## Requirements

1. Extend protocol enum in app-service API if needed:
   - `HTTP`
   - `REST`
   - `GRPC`
   - `TCP`
2. Add Gateway repository support for:
   - `GRPCRoute`
   - `TCPRoute`
3. Map protocols:
   - `HTTP`/`REST` -> `HTTPRoute`
   - `GRPC` -> `GRPCRoute`
   - `TCP` -> `TCPRoute`
4. Add status mapping for each route type.
5. Extend Cilium ingress policy logic for TCP ports.
6. Preserve public Swagger requirement:
   - internet gateway exposure still requires a public Swagger page
   - if non-HTTP services cannot provide OpenAPI docs, require a CloudForge documentation adapter before exposure
7. Update local examples for gRPC if practical.

## Acceptance Criteria

- HTTP app-service behavior is unchanged.
- gRPC route creation is covered by tests.
- TCP route creation is covered by tests if Gateway API version supports it.
- Unsupported protocol/route combinations return clear validation errors.
- Public exposure for gRPC/TCP without docs metadata is rejected.
