# Task 35 — CF App Service Local Dev Loop And Examples

## Context

CF App Service must be easy to validate locally. The existing default loop is `make dev`, which starts Docker backing services, k3d, Envoy Gateway, and Tilt in Kubernetes mode.

This task adds local examples, smoke tests, and Makefile/Tilt updates needed to exercise private and public app services.

Reference:

- `README.md`
- `dev/README.md`
- `dev/CONNECTIONS.md`
- `dev/HOSTS.md`
- `Tiltfile`
- `Makefile`

## Requirements

1. Add example app services:
   - private REST service
   - public REST service with Swagger
   - worker service
   - optional gRPC service if protocol support exists
2. Add a local app image build flow.
3. Push or load example images into k3d.
4. Add Make targets if useful:
   - `app-example-build`
   - `app-example-deploy-private`
   - `app-example-deploy-public`
   - `app-example-smoke`
   - `app-example-clean`
5. Update Tilt if app examples should be live-reloaded.
6. Update local docs with expected URLs.
7. Add smoke tests for:
   - public app route
   - public Swagger route
   - public OpenAPI JSON
   - private app not reachable from local gateway

## Code Comments And READMEs

- Add README files for every example package or service.
- Comment Makefile targets where ordering matters.
- Avoid hidden local assumptions; document hostnames, ports, and required commands.

## Acceptance Criteria

- `make dev` still starts the platform.
- Example public REST app can be deployed locally.
- Example public Swagger page is reachable from localhost.
- Example private REST app is not reachable through Envoy Gateway.
- Cleanup target removes example resources.
- Docs explain how to run the examples from zero.

## Validation

Run:

```bash
make dev
make app-example-build
make app-example-deploy-public
make app-example-smoke
make app-example-clean
```

If Makefile targets are not added, document the exact replacement commands in the example README.
