# `internal/rest` — CF-Provisioner HTTP API

This package is the **HTTP boundary** for CF-Provisioner: it turns JSON requests into calls on
[`ProvisionerService`](../service/) and maps results and errors back to **OpenAPI-shaped** JSON
responses. It is not the place for infrastructure logic; that stays in `internal/service` and
`internal/repository`.

## What this API does

- Exposes versioned REST routes under `/v1/...` as defined in `api/cf-provisioner/v1/openapi.yaml`.
- **Networks**: start provisioning (`POST /v1/networks`), read status (`GET /v1/networks/{id}`),
  start deprovisioning (`DELETE /v1/networks/{id}`).
- **Jobs**: poll async work (`GET /v1/jobs/{jobId}`), list per network (`GET /v1/networks/{id}/jobs`).
- **Gateways**: provision and remove internet ingress (`POST` / `DELETE …/gateway`), read status
  (`GET …/gateway`).
- **Subnets**: create and list durable private/public subnet metadata.
- **App Services**: generated CF App Service routes are mounted and return typed `501` responses
  until later tasks add app-service persistence, workload reconciliation, and exposure orchestration.
- **CIDR**: operator listing of allocations (`GET /v1/cidr/allocations`).
- Enforces **internal-only** access via header `X-CF-Internal-Secret` (see [server.go](server.go)).

## Why it exists

- **Separation of concerns**: HTTP concerns (status codes, JSON shapes, pagination, auth header) stay
  here; orchestration and infra clients stay in the service layer.
- **Contract stability**: Handlers depend on **generated** request/response types from OpenAPI, so
  clients and servers agree on field names and enums.
- **Safe errors**: [`errors.go`](errors.go) maps typed `CFError` values to HTTP status and a small
  JSON `Error` object (with optional `requestId` from middleware), without leaking raw stack traces.

## Why it matters

- CF-Provisioner is a **control-plane** component: other platform services call it to create tenant
  isolation (vCluster, CIDRs, policies, kubeconfig, optional public routes). A clear REST layer is
  what makes that integration predictable and testable.
- **Async correctness**: long work returns **202 + `Job`**; without a disciplined REST layer, callers
  would not get consistent handles or status codes for polling.

## How it is organized

- **`handler.go`** — Implements `generated.StrictServerInterface`: validate/transform body, call
  service, map errors per operation, encode success DTOs.
- **`models_transform.go`** — Bidirectional mapping between generated OpenAPI types and
  `internal/service` params/DTOs (including UUID parsing and paging helpers).
- **`errors.go`** — `mapServiceError` and `withRequestID` shared by all handlers.
- **`server.go`** — Builds the `http.Handler`: strict OpenAPI mux + middleware chain + internal secret.
- **`handler.go` (bottom)** — `JSONDecodeError` / `JSONEncodeError` for strict server callbacks.
- **`generated/`** — Code generated by oapi-codegen; do not hand-edit (see
  [generated/README.md](generated/README.md)).

Regenerate stubs after OpenAPI changes:

```bash
cd services/cf-provisioner && go generate ./...
```

## Capabilities (summary)

- **Auth**: Rejects requests without correct `X-CF-Internal-Secret` (`401`).
- **Async**: `POST /v1/networks`, `DELETE /v1/networks/{id}`, gateway `POST` / `DELETE` return **202** with a **Job**.
- **Poll**: `GET /v1/jobs/{jobId}` returns job status and optional error message.
- **Status**: `GET /v1/networks/{id}` returns provisioning state and CIDRs when inferrable.
- **Gateway**: Async job for attach/detach; `GET …/gateway` for route-backed status.
- **App Services**: route stubs keep the OpenAPI server/client contract compiled while Task 28+
  implements durable app-service state, Kubernetes workload objects, and Gateway/Cilium routing.
- **Ops**: Paginated `GET /v1/cidr/allocations` and paginated network job lists.
- **Errors**: Typed mapping including **422** for `PROVISIONING_FAILED` (see `errors.go`).

```

  +----------------------------------->| ToServiceProvisionNetworkParams  |
  |                                    | svc.ProvisionNetwork(ctx, ...)   |
  |                                    +----------------------------------->|
  |                                    |                                    | CIDR + Job row (sync)
  |                                    |                                    | go ... async work
  |                                    |<-----------------------------------+
  |<-----------------------------------+ ToJobFromService                 |
  | 202 { Job id, networkId, ... }     |                                    |
  |                                    |                                    |
  | GET /v1/jobs/{jobId}               |                                    |
  +----------------------------------->| svc.GetJob(...)                    |

  |                                    |                                    |
  | GET /v1/networks/{networkId}       |                                    |

```

## Middleware order (why this shape)

`NewRouter` composes (outer to inner):

```
Request --> RequestID --> Logger --> Recovery --> InternalSecretAuth --> OpenAPI mux --> Handler
```

- **RequestID / Logger / Recovery** run first so every attempt is correlated and logged, including
  bad secrets.
- **InternalSecretAuth** sits just **before** the generated mux so all OpenAPI routes share the same
  gate without duplicating checks inside each handler.
